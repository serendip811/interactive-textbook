# 인터랙티브 교재 플랫폼 노트북 v0.1

> 프로젝트명: 미정  
> 문서 성격: 제품 방향과 초기 구현 기준을 함께 기록하는 작업 노트  
> 기준 구현체: Harmony Textbook RC1

---

## 1. 한 문장 정의

> **읽는 것을 넘어, 개념을 직접 보고·듣고·조작하며 이해하는 디지털 교재 플랫폼**

이 플랫폼은 재사용 가능한 학습 블록과 과목별 인터랙티브 도구를 이용해 교재를 제작하고 실행한다. 학습자의 조작, 응답, 진도와 복습 기록을 연결하며, AI는 제작자가 콘텐츠를 구조화하고 예제와 문제를 만드는 과정을 보조한다.

---

## 2. 출발점

기존 PDF, 전자책, 동영상 강의는 내용을 전달하는 데는 효과적이지만 학습자가 개념을 직접 바꾸어 보고 결과를 확인하기는 어렵다.

우리가 만들고자 하는 것은 단순히 화면으로 옮긴 책이 아니다. 학습자가 설명을 읽은 뒤 관련 대상을 직접 움직이고, 값을 바꾸고, 소리를 듣고, 결과를 비교하며 개념을 경험하는 교재다.

첫 번째 기준 구현체인 화성학 교재에서는 다음 경험을 실제로 구현했다.

- PART 0~16, 총 76개 단원
- 개념 설명, 악보, 건반, 오디오, 연습, 문제의 연결
- 악보와 건반을 동일한 음 데이터로 표현
- 전체 진행 듣기와 한 단계씩 듣기
- 재생 단계에 맞춘 건반 하이라이트
- 파트별 체크포인트와 즉시 채점
- 음정 문제, 반음 수 시각화, 자유 건반
- 모바일 목차와 반응형 화면

따라서 현재 단계는 아이디어 검증 단계가 아니다. 화성학에서 확인한 경험을 **콘텐츠 데이터, 공통 플레이어, 학습 블록, 과목별 플러그인**으로 분리하는 단계다.

## 3. 해결하려는 문제

### 학습자의 문제

- 글이나 영상을 보아도 추상적인 개념이 머릿속에 잘 그려지지 않는다.
- 설명을 이해했다고 생각하지만 직접 적용하면 막힌다.
- 틀린 이유를 바로 알기 어렵다.
- 교재, 도구, 문제 풀이와 학습 기록이 서로 분리되어 있다.

### 제작자의 문제

- 인터랙티브 교재 하나를 만들려면 콘텐츠 작성과 웹 개발을 동시에 해야 한다.
- 악보, 그래프, 시뮬레이션 같은 기능을 교재마다 새로 개발한다.
- 콘텐츠와 실행 코드가 결합되면 수정, 검수, 재사용이 어려워진다.
- AI로 초안을 빠르게 만들 수 있어도 정확성을 검수하고 일관된 형식으로 배포하기 어렵다.

## 4. 핵심 가치

### 4.1 경험으로 이해한다

설명만 제공하지 않는다. 이해에 도움이 되는 경우 시각화, 소리, 조작, 비교와 즉시 피드백을 연결한다.

### 4.2 하나의 개념을 여러 표현으로 연결한다

같은 개념을 글, 그림, 그래프, 악보, 건반, 소리, 수식 등으로 연결해 표현한다. 각 표현은 따로 움직이는 장식이 아니라 가능한 한 동일한 원본 데이터를 공유한다.

예를 들어 화성학의 음 데이터 하나가 다음을 동시에 만든다.

- 오선보의 음표
- 건반의 하이라이트
- 재생되는 소리
- 문제의 정답과 해설

### 4.3 학습 목표에 맞는 상호작용을 사용한다

모든 개념을 억지로 시각화하거나 조작하지 않는다. 조작이 이해에 실질적으로 도움이 되는 지점에만 인터랙션을 사용한다.

### 4.4 즉시 피드백을 제공한다

학습자가 답을 제출하거나 대상을 조작하면 결과와 이유를 가능한 한 바로 보여준다.

### 4.5 콘텐츠와 실행 기술을 분리한다

교재 내용은 구조화된 데이터로 관리하고, 플랫폼은 이를 공통 UI와 과목별 도구로 실행한다. 같은 콘텐츠를 웹, 모바일, 오프라인 패키지 등 여러 환경에서 재사용할 수 있어야 한다.

### 4.6 AI가 만들고 사람이 책임진다

AI는 초안, 예제, 문제, 변형 문제와 메타데이터 생성을 돕는다. 그러나 교육 콘텐츠의 최종 정확성과 공개 여부는 제작자 또는 검수자가 책임진다.

## 5. 제품의 세 영역

플랫폼은 다음 세 영역으로 구분한다.

| 영역 | 역할 | 초기 우선순위 |
|---|---|---:|
| 교재 라이브러리 | 교재 탐색, 상세 정보, 저장, 이어보기 | 높음 |
| 학습 플레이어 | 콘텐츠 렌더링, 조작, 문제 풀이, 진도 기록 | 최우선 |
| 제작 도구 | 블록 편집, AI 보조, 미리보기, 검수, 배포 | 단계적 구현 |

초기 제품의 중심은 **학습 플레이어와 콘텐츠 규격**이다. 완전한 노코드 편집기나 공개 마켓은 콘텐츠 모델이 충분히 검증된 뒤 개발한다.

## 7. 단원의 학습 구조

모든 단원에 동일한 여섯 단계를 강제하지 않는다. 제작자는 학습 목표에 따라 블록을 조합하되 다음 공통 학습 원칙을 따른다.

1. **설명**: 무엇을 배우는지 이해한다.
2. **탐색**: 시각화, 소리 또는 사례로 관계를 발견한다.
3. **조작**: 필요한 경우 값을 바꾸거나 대상을 움직여 본다.
4. **적용**: 문제나 과제를 통해 직접 사용한다.
5. **피드백**: 결과와 틀린 이유를 확인한다.
6. **정리·복습**: 핵심을 정리하고 이후 복습 대상으로 연결한다.

단원에 따라 일부 단계는 합쳐지거나 생략될 수 있다.

예를 들어:

- 음정: 두 음 선택 → 건반 거리 확인 → 소리 비교 → 종류 판별
- 종지: 진행 듣기 → 종지 종류 선택 → 긴장과 마침감 해설
- 성부진행: 음표 이동 → 병행 오류 실시간 표시 → 수정
- 함수: 식의 계수 변경 → 그래프 변화 관찰 → 규칙 설명
- 천문학: 시간 이동 → 천체 위치 변화 관찰 → 예상과 실제 비교

## 8. 콘텐츠 데이터 모델 초안

교재는 하나의 긴 HTML이 아니라 구조화된 데이터로 관리한다. 아래 형식은 개념 검증용 초안이며 구현 과정에서 JSON Schema 등으로 구체화한다.

```yaml
textbook:
  id: harmony-foundations
  title: 화성학의 기초
  version: 0.1.0
  status: reviewed
  subjects: [music, harmony]

  parts:
    - id: intervals
      title: 음정

      lessons:
        - id: interval-2-1
          title: 음정이란
          objectives:
            - 두 음의 도수를 계산할 수 있다

          blocks:
            - id: concept-1
              type: common.markdown
              content: 두 음 사이의 거리를 음정이라고 한다.

            - id: example-1
              type: music.note-sequence
              data:
                sequence:
                  - [C4, E4]
                views: [score, keyboard]
                playback: [together, ascending]

            - id: quiz-1
              type: common.multiple-choice
              question: C에서 E까지는 몇 도인가?
              choices: [2도, 3도, 4도]
              answer: 3도
              explanation: C-D-E를 양 끝 음을 포함하여 센다.

          review:
            reviewer: pending
            theory_verified: false
            interaction_tested: false
```

### 모델 설계 원칙

- 모든 교재, 파트, 단원과 블록은 안정적인 ID를 가진다.
- 콘텐츠와 화면 스타일을 분리한다.
- 문제는 정답뿐 아니라 해설과 검수 상태를 가진다.
- 과목별 블록은 이름 공간을 사용한다. 예: `music.keyboard`, `math.function-graph`.
- 콘텐츠 버전과 실행 엔진 버전을 별도로 관리한다.
- 블록 데이터는 가능한 한 여러 표현에서 공유한다.
- 저장된 학습 기록은 콘텐츠 버전 변경에도 추적 가능해야 한다.

## 9. AI의 역할

AI는 플랫폼의 목적이 아니라 제작 효율과 학습 지원을 높이는 도구다.

### 제작 단계

- 학습자 수준과 목표에 맞춘 목차 초안
- 설명의 난이도 조절
- 예제와 오답 선택지 생성
- 기존 문제의 변형 문제 생성
- 콘텐츠를 플랫폼 블록 데이터로 구조화
- 용어와 표기 일관성 점검
- 누락된 선행 개념 탐지

### 검수 단계

- 데이터 형식 검증
- 정답과 해설의 논리적 불일치 후보 탐지
- 악보·건반·오디오 데이터의 불일치 탐지
- 유사하거나 반복되는 문제 표시
- 접근성과 난이도 문제 후보 표시

### 학습 단계의 향후 기능

- 틀린 답에 맞춘 추가 설명
- 같은 개념의 다른 예제 제시
- 학습 기록에 따른 복습 문제 구성
- 학습자의 질문을 현재 단원 문맥에서 설명

### 원칙

- AI 생성 여부와 검수 상태를 내부적으로 추적한다.
- 검수되지 않은 콘텐츠는 공식 교재로 공개하지 않는다.
- 정답이 하나가 아닌 문제는 단일 정답처럼 자동 채점하지 않는다.
- AI 설명은 교재 원문과 충돌할 경우 이를 명확히 표시한다.

## 10. 첫 번째 기준 구현체: 화성학

화성학 교재는 단순한 첫 콘텐츠가 아니라 플랫폼 구조를 설계하기 위한 기준 구현체다.

### 현재 확보된 자산

- 76개 단원의 커리큘럼
- 단원별 설명과 요약
- 음과 화음의 구조화된 예제 데이터
- 악보 렌더링 경험
- 건반 렌더링과 음 이름 표시
- Web Audio 기반 재생
- 재생 단계와 건반의 동기화
- 음정 전용 연습과 객관식 채점
- 파트별 체크포인트

### 현재 구조의 한계

- 약 5,800줄의 단일 HTML에 콘텐츠와 코드가 결합되어 있다.
- 많은 직접 연습이 서술형 안내에 머문다.
- 비슷한 연습문제가 여러 단원에서 반복된다.
- 진도, 오답, 북마크와 메모가 저장되지 않는다.
- 새로고침하면 퀴즈 상태가 사라진다.
- 오디오, 악보와 건반 코드가 파일 내부에 누적되어 유지보수가 어렵다.
- VexFlow 외부 CDN 의존으로 완전한 오프라인 사용이 어렵다.
- 재생 중지, 키보드 포커스 등 접근성을 보강해야 한다.
- 콘텐츠 버전과 이론 검수 이력을 관리하지 않는다.

### 이전 원칙

기존 HTML에 플랫폼 기능을 계속 덧붙이지 않는다. 먼저 일부 단원을 새 데이터 모델과 플레이어로 재구축한 뒤 동등한 학습 경험이 재현되는지 검증한다.

## 11. MVP 범위

### MVP에서 반드시 구현한다

- 교재 목록과 상세 화면
- 단원별 학습 플레이어
- 교재·파트·단원·블록 콘텐츠 규격
- 본문, 이미지, 예제, 퀴즈, 해설, 요약 블록
- 음악 악보, 건반, 오디오 플러그인
- 재생과 시각화 동기화
- 진도 저장과 이어보기
- 문제 응답과 오답 기록
- 북마크
- 모바일 대응
- 내부 제작용 데이터 편집 또는 폼
- 미리보기와 검수 상태 표시

### MVP 이후로 미룬다

- 누구나 사용하는 완전한 노코드 편집기
- 외부 제작자 공개 등록
- 교재 판매 마켓과 수익 분배
- AI 완전 자동 교재 생성·공개
- 교사·학급·과제 관리
- 모든 과목의 시뮬레이터
- 실시간 공동 편집
- 고급 학습 분석 대시보드

## 13. 개발 순서

### 단계 1. 기준 단원 이전

- 화성학에서 성격이 다른 3~5개 단원을 선정한다.
- 기존 콘텐츠를 구조화된 데이터로 분리한다.
- 공통 플레이어와 음악 플러그인의 최소 버전을 만든다.
- 기존 HTML과 동일하거나 더 나은 경험이 재현되는지 확인한다.

추천 기준 단원:

- 음정: 시각적 거리와 문제 풀이
- 3화음: 악보·건반·오디오 동기화
- 종지: 순차 재생과 듣기 판별
- 성부진행: 규칙 기반 직접 조작
- 화성 분석: 정답이 하나가 아닐 수 있는 고급 활동

### 단계 2. 학습 기록

- 진도 저장
- 이어보기
- 문제 응답과 오답 기록
- 북마크
- 복습 대상 생성

### 단계 3. 화성학 전체 이전

- 76개 단원을 새 포맷으로 변환한다.
- 반복 문구와 반복 문제를 정리한다.
- 각 단원의 목표에 맞는 조작형 활동을 추가한다.
- 이론 정확성, 악보, 건반과 재생 데이터를 다시 검수한다.

### 단계 4. 두 번째 교재 검증

음악과 기술 구조가 다른 짧은 교재를 제작해 범용성을 확인한다.

후보:

- 함수와 그래프
- 기초 역학
- 태양계와 궤도

두 번째 교재에서 실제로 반복되는 기능만 공통 플랫폼 기능으로 승격한다.

### 단계 5. 제작 도구와 AI 보조

- 내부 제작용 편집 화면
- AI 초안과 블록 데이터 생성
- 검수 워크플로
- 버전 관리와 배포

### 단계 6. 외부 확장

- 외부 제작자 도구
- 교재 공유와 복제
- 공개 라이브러리
- 필요할 경우 판매와 정산

## 14. 성공 기준

### 학습 경험

- 학습자가 설명을 읽은 뒤 실제로 개념을 조작할 수 있는가?
- 시각화와 조작이 장식이 아니라 이해에 기여하는가?
- 잘못된 답이나 조작에 이유가 포함된 피드백을 제공하는가?
- 같은 개념의 여러 표현이 서로 일치하는가?

### 제작 경험

- 새 단원을 만들 때 실행 코드를 직접 수정하지 않아도 되는가?
- 같은 블록을 다른 교재에서 재사용할 수 있는가?
- 콘텐츠 수정이 악보, 건반, 오디오 등에 일관되게 반영되는가?
- AI가 만든 결과를 사람이 쉽게 검수하고 수정할 수 있는가?

### 기술 품질

- 콘텐츠 데이터와 실행 엔진이 분리되어 있는가?
- 블록과 플러그인이 독립적으로 테스트 가능한가?
- 모바일, 키보드와 스크린리더 사용을 고려했는가?
- 콘텐츠와 학습 기록의 버전 호환성을 관리할 수 있는가?

## 15. 하지 않을 것

- 단순히 HTML 파일을 모아 보여주는 호스팅 서비스로 만들지 않는다.
- 모든 단원에 똑같은 학습 순서를 강제하지 않는다.
- 시각화가 필요하지 않은 개념에 억지로 애니메이션을 넣지 않는다.
- AI가 생성한 콘텐츠를 검수 없이 공식 교재로 공개하지 않는다.
- 첫 버전부터 모든 과목, 제작자, 교사와 마켓 기능을 지원하지 않는다.
- 기존 화성학 단일 HTML에 플랫폼 기능을 계속 누적하지 않는다.

## 16. 장기 비전

> **세상에서 가장 이해하기 쉬운 디지털 교재를 만드는 플랫폼**

학습자는 글만 읽는 대신 개념을 직접 실험하고 즉시 피드백을 받는다. 제작자는 코드를 처음부터 개발하지 않고도 공통 학습 블록과 과목별 도구를 조합해 교재를 만든다. AI는 제작과 개인화를 돕고, 사람은 교육적 판단과 정확성을 책임진다.

영상보다 필요한 부분을 빠르게 탐색할 수 있고, PDF보다 깊게 상호작용하며, 개별 앱보다 쉽게 제작하고 확장할 수 있는 새로운 형태의 교재를 지향한다.

## 17. 현재의 핵심 결정

1. 제품의 중심 가치는 AI가 아니라 **인터랙티브한 이해 경험**이다.
2. AI는 교재 제작과 검수를 돕는 핵심 수단으로 사용한다.
3. 초기 제품은 학습 플레이어와 콘텐츠 규격에 집중한다.
4. 콘텐츠 데이터, 공통 블록과 과목별 플러그인을 분리한다.
5. 화성학 교재의 재구축 과정을 플랫폼 개발 1단계로 삼는다.
6. 두 번째 교재로 공통 구조의 범용성을 검증한다.
7. 완전한 저작 도구, 마켓과 외부 제작자 기능은 이후 단계로 미룬다.

# 인터랙티브 교재 플랫폼 정의서

> 문서 버전: v0.1-platform  
> 프로젝트명: 미정  
> 문서 상태: 제품 구조 정의 초안  
> 첫 번째 기준 교재: 화성학 인터랙티브 교재 RC1

---

## 1. 문서 목적

이 문서는 인터랙티브 교재 플랫폼의 제품 정체성, 핵심 학습 경험, 콘텐츠 구조, 기술적 경계와 초기 개발 범위를 정의한다.

기존 비전 문서가 “왜 만드는가”를 설명했다면, 이 문서는 다음 질문에 답하는 것을 목표로 한다.

- 플랫폼은 정확히 어떤 제품인가?
- 학습자와 제작자에게 어떤 가치를 제공하는가?
- 교재와 플랫폼은 어떻게 분리되는가?
- 공통 기능과 과목별 기능은 어떻게 구분되는가?
- AI는 제작 과정에서 어떤 역할을 하는가?
- 첫 번째 MVP는 어디까지 만드는가?
- 기존 화성학 교재를 어떻게 새 구조로 이전하는가?

이 문서는 최종 기술 명세가 아니다. 화성학 교재와 두 번째 시험 교재를 통해 구조를 검증하면서 계속 수정한다.

---

## 2. 배경

기존 디지털 학습 자료는 대체로 다음 형식에 머문다.

- PDF와 전자책: 읽기에는 편하지만 개념을 직접 조작하기 어렵다.
- 동영상 강의: 이해하기 쉽지만 원하는 부분을 빠르게 탐색하거나 직접 실험하기 어렵다.
- 개별 학습 앱: 상호작용은 풍부하지만 새로운 교재를 만들 때마다 앱을 다시 개발해야 한다.
- 일반 문서 도구: 제작은 쉽지만 악보, 시뮬레이션, 채점 같은 전문 학습 기능이 약하다.

화성학 교재 RC1을 제작하면서 설명, 악보, 건반, 소리, 퀴즈를 하나의 학습 흐름으로 연결할 수 있음을 확인했다. 동시에 모든 콘텐츠와 실행 코드가 하나의 대형 HTML 파일에 결합되면서 유지보수와 확장에 한계가 생겼다.

이 프로젝트는 화성학 교재에서 검증된 경험을 재사용 가능한 교재 엔진으로 분리하고, AI와 사람이 새로운 인터랙티브 교재를 더 쉽게 제작할 수 있도록 발전시키는 작업이다.

---

## 3. 제품 비전

> **AI와 사람이 함께 인터랙티브 교재를 만들고, 검증하고, 배포하며 학습하는 플랫폼**

학습자는 설명을 읽는 데서 끝나지 않는다. 개념을 눈으로 확인하고, 직접 조작하고, 결과를 비교하며, 즉시 피드백을 받는다.

제작자는 매번 새로운 웹사이트나 앱을 처음부터 개발하지 않는다. 공통 학습 블록과 과목별 도구를 조합하고 AI의 도움을 받아 교재를 제작한다.

장기적으로는 다음을 지향한다.

> 영상보다 빠르게 탐색할 수 있고, PDF보다 이해하기 쉬우며, 독립 앱보다 제작하기 쉬운 새로운 형태의 디지털 교재를 만든다.

## 4. 제품 정의

이 플랫폼은 다음 세 영역으로 구성된다.

### 4.1 교재 제작 환경

- 교재의 파트, 단원, 학습 목표를 구조화한다.
- 공통 블록과 과목별 인터랙션 블록을 조합한다.
- AI를 이용해 목차, 설명, 예제, 문제 초안을 생성한다.
- 제작자가 미리보기, 수정, 검수 후 배포한다.

### 4.2 학습 실행기

- 구조화된 교재 데이터를 일관된 화면으로 렌더링한다.
- 텍스트, 시각화, 조작, 채점, 피드백을 실행한다.
- 목차, 진도, 이전·다음 이동, 모바일 UI를 제공한다.
- 학습자의 점수, 오답, 북마크와 메모를 관리한다.

### 4.3 교재 라이브러리

- 공개된 교재를 탐색하고 선택할 수 있게 한다.
- 교재 소개, 난이도, 대상, 예상 학습시간을 제공한다.
- 이어보기와 복습할 교재를 보여준다.
- 장기적으로 제작자별 교재 배포와 공유를 지원한다.

초기 제품의 중심은 **학습 실행기와 내부 제작 흐름**이다. 누구나 교재를 공개하는 오픈 마켓은 초기 범위에 포함하지 않는다.

## 5. 해결하려는 핵심 문제

### 학습자 문제

- 글이나 영상만으로는 추상적인 개념을 이해하기 어렵다.
- 설명, 시각자료, 연습문제와 도구가 서로 분리되어 있다.
- 문제를 틀려도 왜 틀렸는지 즉시 확인하기 어렵다.
- 학습 진도와 오답이 다음 학습에 충분히 반영되지 않는다.

### 제작자 문제

- 인터랙티브 교재를 만들려면 콘텐츠 작성과 프론트엔드 개발을 모두 해야 한다.
- 악보, 그래프, 시뮬레이션, 채점기를 교재마다 다시 구현해야 한다.
- AI가 생성한 HTML은 빠르게 시제품을 만들 수 있지만 구조, 품질과 유지보수가 일관되지 않다.
- 콘텐츠 수정이 코드 변경과 연결되어 검수와 버전 관리가 어렵다.

### 플랫폼이 제공할 해결책

- 콘텐츠와 실행 코드를 분리한다.
- 반복 가능한 학습 블록을 제공한다.
- 과목별 전문 도구를 플러그인처럼 연결한다.
- AI가 만든 초안을 정해진 데이터 규격으로 변환한다.
- 자동 검사와 사람 검수를 거쳐 배포한다.
- 학습자의 행동과 결과를 다음 복습에 연결한다.

## 6. 초기 사용자

### 6.1 학습자

- 기존 교재나 동영상만으로 개념 이해가 어려운 독학자
- 기초부터 순서대로 학습하려는 입문자
- 특정 개념을 시각적·청각적으로 다시 확인하려는 학습자

### 6.2 내부 제작자

- AI와 함께 교재 초안을 만드는 운영자
- 학습 내용을 검수하는 과목 전문가
- 과목별 인터랙션을 개발하는 개발자

### 6.3 향후 사용자

- 교사와 강사
- 전문 콘텐츠 제작자
- 출판사와 교육기관
- 자신의 수업 자료를 배포하려는 외부 제작자

초기에는 내부 제작자가 품질을 통제한다. 외부 제작자용 공개 저작 도구는 콘텐츠 규격과 검수 체계가 안정된 뒤 제공한다.

## 7. 핵심 원칙

### 7.1 경험으로 이해한다

설명만 제공하지 않고, 이해에 도움이 되는 시각화·소리·조작·비교를 함께 제공한다.

### 7.2 상호작용에는 학습 목적이 있어야 한다

화려함을 위한 애니메이션이나 조작은 사용하지 않는다. 모든 상호작용은 특정 학습 목표와 연결되어야 한다.

### 7.3 공통 구조는 학습 순서를 강제하지 않는다

모든 단원에 동일한 여섯 단계를 억지로 넣지 않는다. 제작자는 목표에 맞는 블록을 선택하되 다음 원칙을 따른다.

> 설명 → 탐색 → 조작 → 피드백 → 적용 → 회상

단원에 따라 일부 단계는 생략하거나 순서를 바꿀 수 있다.

### 7.4 하나의 개념을 여러 표현으로 연결한다

화성학의 악보·건반·소리처럼 동일한 개념 데이터를 여러 관점으로 표현한다. 각 표현은 별도의 예제가 아니라 같은 상태를 공유해야 한다.

### 7.5 콘텐츠와 실행 코드를 분리한다

교재 내용은 구조화된 데이터로 관리하고, 화면과 상호작용은 교재 엔진이 실행한다.

### 7.6 AI 결과는 검수 가능한 초안이다

AI 생성 결과를 자동으로 정답으로 간주하지 않는다. 출처, 규칙 검사, 전문가 검수와 버전 기록을 통해 신뢰도를 관리한다.

### 7.7 범용성보다 검증을 우선한다

처음부터 모든 과목을 위한 완벽한 구조를 만들지 않는다. 실제 교재에서 두 번 이상 반복되어 검증된 기능을 공통 기능으로 승격한다.

## 8. 핵심 학습 경험

### 8.1 학습 흐름

1. 학습 목표를 확인한다.
2. 핵심 설명을 짧게 읽는다.
3. 예제의 변화 과정을 시각적·청각적으로 탐색한다.
4. 값을 바꾸거나 요소를 움직여 직접 실험한다.
5. 예상과 실제 결과를 비교한다.
6. 문제를 풀고 즉시 피드백을 받는다.
7. 틀린 문제와 취약 개념을 다시 연습한다.
8. 단원 요약과 다음 단원 연결점을 확인한다.

### 8.2 화성학에서의 적용 예

| 학습 개념 | 핵심 조작 | 피드백 |
| --- | --- | --- |
| 음정 | 건반 두 개 선택 | 도수, 반음 수, 음정 성질 표시 |
| 화음 | 음을 선택해 화음 구성 | 화음명, 구성음, 빠진 음 안내 |
| 자리바꿈 | 최저음을 변경 | 기본형·1전위·2전위 판별 |
| 종지 | 진행을 듣고 유형 선택 | 정답, 기능과 종결감 설명 |
| 성부진행 | 음표를 드래그해 수정 | 병행5도·8도 등 오류 강조 |
| 화성 분석 | 악보 위에 기호 배치 | 로마숫자·기능 분석 비교 |

### 8.3 피해야 할 패턴

- 모든 단원에 같은 서술형 문제를 반복하는 것
- 학습자가 결과를 보기만 하고 입력하거나 조작하지 않는 것
- 정답 여부만 보여주고 이유를 설명하지 않는 것
- 학습 목표와 무관한 장식성 애니메이션
- 하나의 긴 페이지에 모든 단원을 넣어 탐색과 로딩을 어렵게 하는 것

## 10. 콘텐츠 모델

### 10.1 기본 계층

```text
교재 Book
└── 파트 Part
    └── 단원 Lesson
        └── 블록 Block
            └── 상호작용 상태 및 평가 Activity
```

### 10.2 교재

교재는 다음 메타데이터를 가진다.

- 고유 ID와 버전
- 제목과 소개
- 과목과 주제
- 대상 학습자
- 선수 지식
- 예상 학습시간
- 난이도
- 제작자와 검수자
- 공개 상태
- 사용한 과목별 블록과 버전

### 10.3 단원

단원은 다음 정보를 가진다.

- 고유 ID
- 제목
- 학습 목표
- 선수 단원
- 예상 학습시간
- 블록 목록
- 완료 조건
- 복습 태그

### 10.4 블록

모든 블록은 최소한 다음 공통 필드를 가진다.

```yaml
id: unique-block-id
type: block-type
version: 1
title: optional-title
objective_refs:
  - objective-id
content: {}
settings: {}
```

과목별 블록은 공통 필드 위에 자신의 데이터 규격을 추가한다.

### 10.5 화성학 단원 예시

```yaml
book_id: harmony-foundations
part_id: intervals

lesson:
  id: interval-2-1
  title: 음정이란
  estimated_minutes: 12

  objectives:
    - id: count-degree
      text: 두 음 사이의 도수를 계산할 수 있다.

  blocks:
    - id: concept-1
      type: concept
      objective_refs: [count-degree]
      content:
        markdown: 두 음 사이의 거리를 음정이라고 한다.

    - id: music-example-1
      type: music.sequence
      objective_refs: [count-degree]
      content:
        sequence:
          - [C4, E4]
        views: [score, keyboard]
        playback: [together, ascending]

    - id: interval-picker-1
      type: music.interval-picker
      objective_refs: [count-degree]
      content:
        prompt: 건반에서 장3도를 만들어 보세요.
        root: C4
        accepted_answers:
          - [C4, E4]
      feedback:
        correct: C-D-E를 모두 포함해 세면 3도이다.
        incorrect: 시작음과 끝음을 모두 포함해 다시 세어 보세요.
```

이 데이터에서 악보, 건반, 오디오와 채점 화면을 교재 엔진이 생성한다.

## 11. 블록 체계

### 11.1 공통 블록

첫 번째 버전에서는 다음 블록만 지원한다.

- `concept`: 핵심 설명
- `markdown`: 일반 본문
- `image`: 이미지와 캡션
- `callout`: 정의·주의·팁
- `steps`: 단계별 설명
- `reveal`: 정답 또는 설명 펼치기
- `multiple-choice`: 선택형 문제
- `short-answer`: 짧은 직접 입력
- `compare`: 두 예제 비교
- `summary`: 핵심 요약
- `review-set`: 복습 문제 묶음

### 11.2 음악 전용 블록

- `music.sequence`: 음 또는 화음 진행의 공통 데이터
- `music.notation`: 악보 표현
- `music.keyboard`: 건반 표현과 직접 연주
- `music.playback`: 동시·순차·단계별 재생
- `music.interval-picker`: 음정 선택과 측정
- `music.chord-builder`: 화음 구성
- `music.voice-leading`: 성부진행 수정
- `music.analysis`: 로마숫자와 기능 분석

### 11.3 확장 블록

표준 블록으로 표현하기 어려운 학습 활동을 위해 `custom-interaction` 확장 지점을 둔다.

단, 사용자 임의의 HTML과 JavaScript를 그대로 실행하지 않는다. 확장 블록은 등록, 검토, 권한 제한과 버전 고정을 거쳐야 한다.

## 12. AI 기반 제작 흐름

### 12.1 기본 흐름

```text
학습 주제·대상·목표 입력
→ AI 목차와 단원 초안 생성
→ 블록 규격으로 구조화
→ 예제·문제·정답 생성
→ 자동 검사
→ 제작자 편집
→ 과목 전문가 검수
→ 미리보기
→ 배포
→ 학습 결과와 오류 반영
```

### 12.2 AI가 담당하는 일

- 커리큘럼과 학습 목표 초안
- 개념 설명의 난이도별 변환
- 예제와 오답 선택지 초안
- 적합한 학습 블록 추천
- 기존 콘텐츠의 구조화된 데이터 변환
- 동일 개념의 추가 연습문제 생성
- 문체와 표기 일관성 검사

### 12.3 AI가 단독으로 결정하지 않는 일

- 공개 가능한 최종 정답
- 고위험 분야의 사실 판단
- 교재 전체의 교육과정 적합성
- 서술형 문제의 유일 정답 처리
- 출처와 저작권이 불분명한 자료 사용

### 12.4 AI 생성 정보 기록

각 콘텐츠는 필요에 따라 다음 정보를 기록한다.

- 생성 또는 수정에 사용된 모델
- 생성 시점
- 사용한 지시문 또는 생성 작업 유형
- 자동 검사 결과
- 최종 검수자
- 수정 이력

AI 생성 이력은 학습자 화면에 항상 노출할 필요는 없지만 내부 품질 관리에는 보존한다.

## 13. 검수와 품질 관리

### 13.1 자동 검사

- 콘텐츠 스키마 유효성
- 필수 필드 누락
- 중복 ID
- 존재하지 않는 블록 타입
- 정답과 선택지 불일치
- 음이름·음정·화음 규칙 검사
- 깨진 이미지와 에셋 경로
- 모바일 최소 화면 폭
- 키보드 조작과 접근성 속성
- 교재에서 요구한 플러그인 버전

### 13.2 사람 검수

- 개념 설명의 정확성
- 학습 목표와 활동의 일치
- 정답과 해설의 타당성
- 난이도와 선수 지식
- 표현의 명료성
- 저작권과 출처
- 서술형·분석형 문제의 복수 해석 가능성

### 13.3 배포 상태

```text
draft → generated → reviewed → approved → published → archived
```

공개된 버전은 변경하지 않는다. 수정 시 새 버전을 만들고 기존 학습 기록이 어떤 버전을 기준으로 했는지 보존한다.

## 14. 학습 기록 모델

### 14.1 기록 대상

- 시작한 교재와 단원
- 마지막 학습 위치
- 완료한 단원
- 문제별 시도 횟수
- 선택하거나 입력한 답
- 정답 여부
- 사용한 힌트
- 마지막 복습 시점
- 북마크와 메모

### 14.2 단원 완료 조건

단순히 페이지 끝까지 스크롤했다고 완료로 처리하지 않는다. 단원마다 완료 조건을 설정할 수 있다.

예:

- 필수 블록 열람
- 핵심 조작 활동 1회 완료
- 확인 문제 제출
- 최소 정답률 달성

초기에는 완료 조건을 단순하게 유지하고, 모든 행동을 과도하게 추적하지 않는다.

### 14.3 복습

- 오답이 있는 문제를 다시 제시한다.
- 동일한 학습 목표의 변형 문제를 제공한다.
- 장기간 학습하지 않은 단원을 추천한다.
- 단순 정답률뿐 아니라 반복 시도와 힌트 사용도 참고한다.

## 16. 제작자용 기능

### MVP 제작 방식

초기에는 완전한 노코드 편집기를 만들지 않는다.

- YAML 또는 JSON 기반 콘텐츠 작성
- 본문은 Markdown 지원
- AI를 이용한 초안 생성과 변환
- 실시간 또는 빠른 미리보기
- 오류 목록과 자동 검사 결과
- 배포 전 체크리스트
- Git 기반 변경 이력

### 향후 편집기

- 블록 추가와 순서 변경
- 폼 기반 속성 편집
- 화면에서 직접 본문 수정
- 에셋 업로드와 관리
- 공동 편집과 댓글
- 검수 요청과 승인
- 버전 비교와 이전 버전 복원

편집기는 콘텐츠 규격이 안정된 뒤 개발한다. 초기부터 편집기 UI를 먼저 만들면 규격 변경 비용이 커질 수 있다.

## 17. 패키징과 배포

교재는 하나의 거대한 HTML이 아니라 다음 요소를 가진 패키지로 관리한다.

```text
harmony-book/
├── book.yaml
├── parts/
│   ├── 00-introduction.yaml
│   ├── 01-notes.yaml
│   └── 02-intervals.yaml
├── assets/
├── validations/
└── CHANGELOG.md
```

교재 패키지는 다음을 선언해야 한다.

- 콘텐츠 스키마 버전
- 필요한 공통 블록 버전
- 필요한 과목별 블록 버전
- 에셋 목록
- 교재 버전
- 제작자와 검수 정보

배포 과정에서는 데이터를 검증하고, 필요한 에셋과 코드 버전을 고정한 뒤 학습 실행기에 게시한다.

---

## 18. 보안과 실행 정책

- 교재 콘텐츠에서 임의 JavaScript 실행을 기본적으로 허용하지 않는다.
- HTML 입력이 필요한 경우 허용 태그와 속성을 제한한다.
- 외부 URL, iframe, 미디어 요청을 정책에 따라 제한한다.
- 과목별 확장 블록은 사전에 등록된 코드만 실행한다.
- 사용자 입력은 교재 콘텐츠와 분리해 저장한다.
- 정답 데이터가 클라이언트에 포함될 때 발생할 수 있는 노출을 고려한다.
- 외부 제작자 기능 도입 전 악성 콘텐츠와 저작권 신고 절차를 마련한다.

- 음악 전용 핵심 블록

- 선택형·직접 입력 문제
- 즉시 피드백과 오답 기록
- 모바일 대응
- 콘텐츠 미리보기
- 스키마와 음악 규칙 자동 검사

1. 반음과 온음

### MVP에서 제외

- 외부 제작자 회원가입과 공개 배포
- 교재 판매와 정산
- 커뮤니티와 댓글
- 완전한 노코드 편집기
- 모든 과목용 블록
- 임의 HTML·JavaScript 업로드
- 고급 학습 분석 대시보드
- 완전한 오프라인 패키지
- 76개 단원 전체 이전

## 20. 화성학 교재 이전 계획

### 1단계: 현행 교재 동결

- 현재 RC1을 기준 구현체로 보존한다.
- 기존 화면과 기능 목록을 회귀 테스트 기준으로 정리한다.
- 새 기능을 기존 단일 HTML에 계속 누적하지 않는다.

### 2단계: 데이터 추출

- 파트와 단원 메타데이터 분리
- 개념 설명과 요약 분리
- 음·화음 진행 데이터 분리
- 문제, 정답과 해설 분리
- 공통 문구와 중복 콘텐츠 식별

### 3단계: 핵심 엔진 추출

- 악보 렌더링
- 건반 렌더링
- 오디오 재생
- 진행 상태 동기화
- 객관식 채점

중복되거나 덧붙여진 이벤트 로직은 하나의 상태 관리 흐름으로 통합한다.

### 4단계: 대표 단원 이전

대표 단원 3~5개를 새 구조로 구현한다. 기존 교재와 다음 항목을 비교한다.

- 내용 누락 여부
- 악보와 건반 정확성
- 재생 동기화
- 모바일 사용성
- 문제 채점
- 접근성
- 수정 용이성

### 5단계: 조작형 활동 추가

- 음정 측정기
- 화음 구성기
- 성부진행 오류 수정기

기존의 “직접 확인해 보세요” 안내를 실제 입력과 피드백으로 교체한다.

### 6단계: 전체 이전 판단

대표 단원에서 데이터 규격과 엔진이 안정된 뒤 나머지 71~73개 단원을 순차적으로 이전한다.

## 21. 두 번째 교재를 통한 검증

화성학만으로 플랫폼을 설계하면 음악 전용 구조를 범용 구조로 오해할 수 있다. 따라서 MVP 이후 작은 두 번째 교재를 만든다.

후보:

- 중학교 수학: 함수와 그래프
- 기초 물리: 힘과 운동
- 기초 천문학: 궤도와 중력

두 번째 교재의 목적은 콘텐츠 양을 늘리는 것이 아니라 다음을 확인하는 것이다.

- 공통 블록이 실제로 다른 과목에서도 재사용되는가?
- 과목별 블록의 등록 방식이 충분히 유연한가?
- 학습 기록과 채점 모델이 과목에 종속되지 않는가?
- 제작 과정에서 AI가 안정적으로 구조화 데이터를 만드는가?

두 교재에서 반복되어 검증된 요소만 공통 플랫폼 기능으로 승격한다.

## 23. 성공 지표

초기에는 가입자 수보다 학습 경험과 제작 효율을 측정한다.

### 학습 지표

- 단원 시작 대비 완료율
- 조작형 활동 완료율
- 첫 시도 정답률과 재시도 후 정답률
- 오답 복습 참여율
- 단원별 중도 이탈 지점
- 학습자가 설명 없이 활동 목적을 이해하는 비율

### 제작 지표

- 새 단원 제작에 걸리는 시간
- 코드 수정 없이 만들 수 있는 단원 비율
- 기존 블록 재사용률
- 자동 검사에서 발견된 오류 수
- 배포 후 발견되는 내용·기능 오류 수
- AI 초안 중 실제 채택되는 비율

### MVP 성공 조건 예시

- 대표 단원 전부가 단일 HTML 복사 없이 데이터만으로 구성된다.
- 악보·건반·오디오가 동일한 음악 데이터를 공유한다.
- 콘텐츠 수정에 엔진 코드 수정이 필요하지 않다.
- 학습자가 새로고침하거나 다시 접속해도 진도를 이어갈 수 있다.
- 최소 세 종류의 조작형 학습이 실제 채점과 피드백까지 연결된다.

| 블록 종류가 무한히 증가 | 공통 블록을 작게 유지하고 확장 블록 계약 사용 |
| AI가 잘못된 내용을 생성 | 자동 규칙 검사, 전문가 검수, 버전과 이력 기록 |
| 상호작용이 장식에 머묾 | 모든 활동을 학습 목표와 평가 방식에 연결 |

| 교재별 디자인이 제각각이 됨 | 공통 디자인 토큰과 접근성 기준 제공 |

## 25. 초기 운영 원칙

- 첫 교재는 운영자가 직접 제작하고 공개한다.
- AI 생성 콘텐츠는 검수 완료 전 공개하지 않는다.
- 공개 교재에는 버전과 검수 상태를 표시한다.
- 학습자의 오류 제보를 단원과 블록 단위로 접수한다.
- 기능보다 콘텐츠 정확성 문제를 우선 수정한다.
- 새 블록은 하나의 특수 사례가 아니라 반복 가능성이 확인될 때 추가한다.
- 외부 제작자 기능은 품질 기준과 신고 절차가 준비된 뒤 연다.

## 26. 아직 결정하지 않은 사항

- 프로젝트명과 브랜드
- 초기 핵심 학습자 연령과 난이도
- 웹 전용 또는 모바일 앱 동시 제공 여부
- 계정 없이 로컬 진도 저장을 먼저 제공할지 여부
- 콘텐츠 스키마의 최종 형식 YAML, JSON 또는 혼합 방식
- 음악 악보 엔진의 장기 선택
- 두 번째 검증 과목
- 무료·구독·교재별 결제 등 수익 모델
- 외부 제작자 공개 시점과 검수 정책
- 콘텐츠 출처 표시와 인용 규격

이 항목은 플랫폼 핵심 구조를 검증한 후 결정한다.

## 27. 최종 정의

이 프로젝트는 인터랙티브 HTML 파일을 모아놓는 저장소가 아니다.

또한 처음부터 모든 과목과 모든 제작자를 지원하는 거대한 교육 마켓도 아니다.

> **구조화된 교재 데이터와 재사용 가능한 학습 블록을 기반으로, AI와 사람이 정확하고 조작 가능한 디지털 교재를 만들고 학습하는 플랫폼이다.**

첫 번째 목표는 화성학 교재를 이 구조로 재구축하여 콘텐츠와 엔진의 분리가 실제로 작동함을 증명하는 것이다. 이후 서로 다른 두 번째 과목을 통해 공통성을 검증하고, 검증된 요소만 점진적으로 플랫폼 기능으로 확장한다.

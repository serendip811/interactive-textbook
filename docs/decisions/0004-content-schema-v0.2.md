# ADR 0004 — 콘텐츠 스키마 v0.2 안정화

- 상태: 채택
- 날짜: 2026-08-24

## 결정

교재 문서는 `schemaVersion`, `contentVersion`, `engineVersion`을 각각 관리한다.

- `schemaVersion`: 문서 구조 버전. 현재 `0.2.0`이며 구조가 바뀔 때만 변경한다.
- `contentVersion`: 교재 내용 버전. SemVer를 사용하고 내용·정답·학습 흐름 변경을 추적한다.
- `engineVersion`: 콘텐츠가 요구하는 최소 엔진 버전. 현재는 정확한 SemVer를 기록한다.
- `blockVersion`: 개별 블록 데이터 계약 버전. 모든 블록에 필수이며 현재 `1.0.0`이다.

ID는 소문자 영숫자로 시작하고 `.` 또는 `-`로 계층을 구분한다. 한 교재 안에서 교재·파트·단원·목표·데이터·블록 ID는 모두 유일해야 한다. 이미 공개된 ID는 학습 상태의 키이므로 의미가 유지되는 한 변경하지 않는다.

## 필드와 참조

- 교재 필수: `id`, 세 버전, `subject`, `title`, `language`, `parts`
- 단원 필수: `id`, `title`, `objectives`, `blocks`, `completion`
- 블록 필수: `id`, `type`, `blockVersion`, `objectiveRefs`, `data`
- `objectiveRefs`는 같은 단원의 목표만 참조한다.
- `dataRefs`는 같은 단원의 `data` 항목만 참조한다.
- 선수 단원과 완료 조건의 참조는 실제 존재하는 ID여야 한다.
- 의미 데이터는 `lesson.data`에 한 번 정의하고 여러 View·Activity가 `dataRefs`로 공유한다.

## 변경 정책

- Patch: 오탈자, 해설, 스타일처럼 구조·판정·상태 호환성을 깨지 않는 변경
- Minor: 선택 필드나 새 블록 형식 추가처럼 기존 콘텐츠가 그대로 동작하는 변경
- Major: 필수 필드 변경, 필드 제거, 의미 변경처럼 마이그레이션이 필요한 변경
- 마이그레이션은 원본을 수정하지 않는 단방향 순수 함수로 제공한다.
- 지원하지 않는 스키마·블록 버전은 배포 전 검증에서 실패시킨다.

## v0.1에서 v0.2로

`migrateBookFrom010`은 `schemaVersion`을 `0.2.0`으로 바꾸고 모든 블록에 `blockVersion: 1.0.0`을 추가한다. 기존 ID, 데이터, 완료 조건은 유지한다. 두 공식 교재는 소스 자체를 v0.2로 이전했으며 함수는 과거 콘텐츠를 가져올 때만 사용한다.

## 결과

콘텐츠와 엔진 릴리스를 독립적으로 추적할 수 있고, 끊어진 참조·중복 ID·미지원 블록·잘못된 객관식 정답·접근성 이름 누락을 배포 전에 검사할 수 있다.

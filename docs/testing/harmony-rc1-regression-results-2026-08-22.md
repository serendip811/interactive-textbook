# Harmony RC1 Phase 0 회귀 테스트 결과

> 실행일: 2026-08-22  
> 대상: 공개 GitHub Pages의 `legacy/harmony-rc1/harmony_textbook_rc1.html`  
> 연결 계획: `docs/testing/harmony-rc1-regression-plan.md`

## 결론

Phase 0을 통과한다. P0 내용 오류나 핵심 기능 불능은 발견되지 않았다. 재생 취소가 없어 여러 듣기를 겹쳐 실행할 수 있는 RC1-002는 P1 수용 위험으로 남기고 Engine v0.1의 단일 재생 세션 요구사항으로 이전한다.

## 결과 요약

| 항목 | 결과 | 증거·메모 |
|---|---|---|
| 정적 회귀 테스트 11개 | PASS | `node --test tests/harmony-rc1-static.test.mjs` |

| 재생 정지·중첩 방지 | FAIL · 수용 | 전역 재생 세션과 취소 API가 없어 기존 예약 음과 새 재생이 공존할 수 있음 |

브라우저 확장 자체의 메타데이터 전송 오류는 있었지만 페이지 URL에서 발생한 콘솔 오류는 없었다.

## RC1-002 재현과 판정

1. `8-5`의 악보 예제 듣기를 시작한다.
2. 종료 전 같은 단원의 전체 진행 듣기 또는 다른 단원의 듣기를 시작한다.
3. 첫 재생은 모든 음을 Web Audio 시간축에 미리 예약하며 취소 핸들을 보관하지 않는다.
4. 새 재생도 같은 `AudioContext`에 음을 추가하므로 이전 예약을 정지하지 못한다.

RC1은 동결하므로 이 구조를 크게 수정하지 않는다. Engine v0.1은 다음 조건을 만족해야 한다.

- 재생 세션은 한 번에 하나만 활성화한다.
- 새 재생을 시작하면 이전 oscillator·timeout·UI 진행을 취소한다.
- 정지, 재시작, 단원 이동 후에도 건반 하이라이트와 진행 상태를 초기화한다.

## Phase 0 통과 근거

- 자동 테스트가 모두 통과했다.
- 대표 5개 단원과 `14-4`를 실제 브라우저에서 확인했다.
- 데스크톱·iPhone 화면 증거와 단계 재생 GIF를 남겼다.
- P0 오류는 없고 P1 위험은 Engine 요구사항으로 명시했다.
- RC1의 보존 위치, 실행 방법, 유지보수 경계와 Engine 이전 기준이 문서화됐다.

# Harmony RC1 회귀 테스트 계획

> 기준 구현체: `legacy/harmony-rc1/harmony_textbook_rc1.html`  
> 작성일: 2026-08-22  
> 연결 문서: `docs/audits/harmony-rc1-known-issues.md`  
> 목적: RC1 버그 수정과 Engine 이전 전후에 핵심 학습 경험이 나빠지지 않았는지 동일한 기준으로 판정한다.

## 실행 계층

| 계층 | 실행 방법 | 현재 상태 |
|---|---|---|
| 정적 구조 | `npm test` | 자동화 완료 |
| 데스크톱 브라우저 | 공개 GitHub Pages에서 수동 시나리오 실행 | 부분 실행: 대표 화면 5개·스트레스 화면 1개·단계 재생 GIF 저장 |
| 모바일 브라우저 | 320·375·390·768·900px 및 iOS Safari | 부분 실행: iPhone Safari 약 393px PASS |
| 내용 검수 | 화성학 전문가가 PART 10~16 우선 검수 | 실행 대기 |

정적 테스트는 구조와 데이터의 회귀를 막지만 실제 소리, VexFlow 화면, 모바일 배치와 사용자 제스처 정책까지 보장하지 않는다.

## 공통 실행 준비

```bash
python3 -m http.server 8000
```

브라우저에서 다음 주소를 연다.

```text
http://localhost:8000/legacy/harmony-rc1/harmony_textbook_rc1.html
```

테스트 시작 전 새로고침하고 개발자 도구 콘솔 오류를 비운다. 오디오 테스트는 음소거를 해제하고 사용자의 첫 클릭으로 AudioContext를 활성화한다.

## 자동 회귀 테스트

`tests/harmony-rc1-static.test.mjs`가 다음을 검사한다.

- 17개 PART, 76개 단원과 고유 ID
- 악보 119개, 단원 건반 76개, 전체 듣기 195개, 단계 듣기 75개
- 체크포인트 14개와 문제 56개
- 모든 `data-sequence` JSON과 Pitch 토큰
- 단원 건반과 전체 듣기 데이터 일치
- 악보와 듣기 데이터 일치
- `2-4`만 단계 재생이 없는 현재 기준
- C♯/D♭, F♯/G♭의 소리 동일성과 도수 차이
- 주요 음정의 도수·반음 수
- 장·단·감·증3화음 대표 데이터
- 체크포인트 정답이 선택지에 존재하는지
- VexFlow 4.2.2 버전 고정

## 수동 회귀 시나리오

### REG-PLAY-001 전체 진행 듣기

- 대상: `1-2`, `4-2`, `8-5`
- 절차: 전체 진행 듣기를 한 번 누르고 모든 단계가 끝날 때까지 기다린다.
- 합격: 단계가 순서대로 한 번씩 들리고 버튼이 종료 후 다시 활성화된다.
- 합격: 콘솔 오류가 없고 마지막 단계 뒤 추가 음이 재생되지 않는다.
- 연결 이슈: RC1-002, RC1-006

### REG-PLAY-002 한 단계씩 듣기

- 대상: `1-2`, `2-3`, `4-2`, `8-5`, `15-2`
- 절차: 단계 수보다 한 번 더 버튼을 누른다.
- 합격: 한 클릭에 한 단계만 들리고 마지막 다음 클릭은 첫 단계로 돌아간다.
- 합격: 빠르게 두 번 눌러도 한 클릭당 음이 중복 실행되지 않는다.
- 연결 이슈: RC1-001, RC1-006

### REG-PLAY-003 건반 하이라이트 동기화

- 대상: `4-2`, `8-5`
- 절차: 전체 듣기와 단계 듣기를 각각 실행한다.
- 합격: 현재 들리는 음만 `lit` 상태이며 악보·라벨과 같은 구성음을 표시한다.
- 합격: 진행 표시가 `현재 단계 / 전체 단계`와 일치한다.
- 연결 이슈: RC1-005, RC1-006

### REG-PLAY-004 정지·재시작과 중첩 재생

- 대상: `8-5`
- 절차: 긴 전체 진행 중 같은 버튼과 다른 단원의 듣기 버튼을 누른다.
- 현재 기대: RC1에는 정지 기능이 없어 중첩 가능성을 기록한다.
- Engine 합격: 새 재생을 시작하면 이전 재생이 정지되고 첫 단계부터 일관되게 시작한다.
- 연결 이슈: RC1-002
- 2026-08-22 결과: 전체 재생 종료와 버튼 재활성화는 PASS. 전역 취소가 없어 중첩 방지는 FAIL이며 Engine v0.1 수용 위험으로 기록.

### REG-PITCH-001 플랫·샵 표기

- 대상: `1-3`, `2-3`, `12-2`, `13-5`
- 절차: C♯/D♭, F♯/G♭ 예제의 악보, 건반 라벨과 소리를 비교한다.
- 합격: 같은 건반과 소리를 사용하되 원래의 음 이름은 악보와 라벨에 보존된다.
- 합격: 플랫이 임의로 샵 표기로 바뀌어 설명되지 않는다.
- 연결 이슈: RC1-005

### REG-INTERVAL-001 음정 도수

- 대상: `2-1`, `2-2`, `2-3`, `2-4`
- 데이터: C–C♯=1도, C–D♭=2도, C–E=3도, C4–E5=10도, C4–C6=15도
- 합격: 글자 이름과 옥타브를 포함한 도수가 기대값과 일치한다.

### REG-INTERVAL-002 반음 수

- 대상: `1-2`, `2-3`, `2-4`
- 데이터: E–F=1, C–D=2, C–E♭=3, C–E=4, C–F♯=6, C4–C5=12
- 합격: 반음 눈금의 시작은 0, 끝 숫자는 실제 반음 수와 일치한다.
- 합격: 하행 예제도 절댓값 거리로 올바르게 표시한다.

### REG-CHORD-001 화음 구성음

- 대상: `4-2`
- 데이터: C–E–G=장3화음, C–E♭–G=단3화음, B–D–F=감3화음, C–E–G♯=증3화음
- 합격: 악보·건반·오디오가 같은 세 음을 사용하고 설명의 화음 종류와 일치한다.
- 연결 이슈: RC1-005

### REG-CONSISTENCY-001 악보·건반·오디오 일치

- 대상: 대표 단원 5개
- 절차: 각 단계의 `data-sequence`, 악보 표기, 건반 하이라이트와 실제 음을 비교한다.
- 합격: 누락·추가·옥타브 차이 없이 동일하다.
- 합격: 진행 순서가 네 표현에서 같다.

### REG-QUIZ-001 객관식 채점

- 대상: PART 4, PART 8, PART 15 체크포인트
- 절차: 정답과 오답을 각각 선택한다.
- 합격: 정답은 초록, 오답은 오답과 정답을 구분해 표시하고 설명을 노출한다.
- 합격: 점수는 정답으로 답한 문항 수와 일치하고 한 문항이 중복 계산되지 않는다.
- 연결 이슈: RC1-012

### REG-MOBILE-001 모바일 건반 배치

- 대상 너비: 320px, 375px, 390px, 768px, 899px, 900px, 901px
- 대상: `1-3`, `2-4`, `4-2`, 자유 건반
- 합격: 흰 건반과 검은 건반이 분리되거나 옆 키 영역으로 넘어가지 않는다.
- 합격: 현재 음으로 스크롤해도 버튼·라벨·반음 눈금이 잘리지 않는다.
- 합격: 세로·가로 회전 후 C4 중앙 이동과 건반 위치가 다시 계산된다.

### REG-A11Y-001 키보드와 상태 알림

- 절차: 마우스 없이 Tab, Enter, Space, Escape로 목차·듣기·퀴즈·자유 건반을 사용한다.
- 합격: 포커스가 보이고 버튼 순서가 화면 흐름과 일치한다.
- 현재 기록: 자유 건반은 Escape로 닫히지만 포커스 이동·복귀는 구현되지 않았다.
- Engine 합격: Drawer를 열면 내부로 포커스가 이동하고 닫으면 실행 버튼으로 돌아간다.
- 연결 이슈: RC1-008, RC1-009

## Phase 0 통과 판단

- 모든 자동 테스트가 통과한다.
- 대표 5개 단원의 데스크톱 핵심 시나리오가 실행된다.
- P0 내용 오류와 핵심 기능 불능 문제가 없다.
- P1 문제는 수정하거나 Engine 이전 시 수용할 위험으로 명시한다.
- 대표 화면 6개와 최소 한 개의 진행 재생 기록을 남긴다.

2026-08-22 실행 결과는 `docs/testing/harmony-rc1-regression-results-2026-08-22.md`에 기록했다. 위 조건을 충족했으며 RC1-002를 명시적 P1 수용 위험으로 남기고 Phase 0을 통과한다.
